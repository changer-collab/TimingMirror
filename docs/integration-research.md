## 1. CSV 导入

**字段（候选 v3，`m0/csv-input/schema.candidate.json`）**

- 输入列：日期（YYYY-MM-DD）/ 标的（6 位数字、字符串、保留前导零）/ 方向（买入|卖出）/ 价格（>0，≤2 位小数）/ 数量（正整数）/ 费用（可空）/ 税费（可空）。
- 标准化交易：`trade_id`（T001…，按原始行序，排序不改写）＋ `trade_date / symbol / side / price / quantity / fee / tax / fee_missing / tax_missing / source{file,line}`。
- 整批语义：`blocked`（任一行级错误→整批不上数）、`warnings[]`、`errors[]`（一次性汇总全部可检测错误）。
- 文件格式：UTF-8（允许 BOM）、逗号分隔、中文表头、LF/CRLF，v1 仅此一种。

**依赖**

- UI 侧（吴涵晶）：确认列表、警告标注（费用/税费缺失、未知列）、错误汇总展示。
- 计算侧（本包）：仅消费标准化交易与排序规则（Q7）；费用/税费不入公式（Q1，见 `m0/calc-baseline`）。
- 验收：R1（改一笔卖出受影响指标按预期变化，已有 A/A′ 夹具）、R5（不上传、断网可算）。
- 【未定】Papa Parse 引入方式：仓库现为零 npm 依赖；T2-4 指定 Papa Parse，vendored 文件或依赖管理需负责人确认（候选方案：单文件 vendor 到 `src/vendor/`，保持零构建）。

**风险**

- 精度策略（≤2 位小数超限直接报错、不自动舍入，Q4）对真实用户数据容忍度低——错误提示必须给出行号与修正指引（O1 已要求汇总）。
- 整批阻断（O1）意味着一个错行全单不可算；演示与文档需明确这一"严格模式"是 v1 选择。
- 截断账单（无期初持仓）会命中 E_QTY_EXCEEDS 阻断（O3）；真实用户常见，需在导入页明示。
- 未知列忽略＋警告（Q5）；中文表头拼写差异（如"成交金额"）会触发缺列 E_HEADER_MISSING，需给出期望列清单。

## 2. 行情缓存

**字段（候选 v1.1，`m0/market-cache/schema.candidate.json`）**

- 支持范围 manifest：`symbols / date_range / data_source / calendar_source / adjustment_basis / pull_evidence / asOfDate`（**当前全部"未提供"**，待 M0-C2 尹辰产出→负责人签收）。
- 日线双序列：`bars`（不复权，金额估值唯一来源）＋ `bars_fwdadj`（前复权快照，仅走势展示）；字段 `date + OHLC + volume`（OHLC 必填，§4-2）。
- 估值接口：入参 `valuation_date`（产品固定传 asOfDate，F-3）→ 出参 `requested_date / effective_date / prices{symbol: 不复权 close}`；非交易日映射按交易日历；缺价 E_PRICE_MISSING 不回退；早于账单末笔 E_VALUATION_BEFORE_LAST_TRADE；超范围 E_VALUATION_OUT_OF_RANGE。
- 快照元信息：`snapshot_id / fetch_time / adjustment_basis`（四者分开记录，B6）。
- 股数事件：v1 不支持送转拆配股；持有区间命中事件生效日→阻断受影响结果（真实识别依据未提供，M3）。

**依赖**

- M0-C2（尹辰）：akshare 前复权/不复权拉数、真实清单草案、复权基准核验记录、拉数成功证据。
- 计算引擎（M1-C3/C4）：估值日解析、单标的与组合阻断语义；反事实路径的持有区间分别检查（B5）。
- 契约历史情境模拟（F-9）：需按标的+历史日期读取涨跌幅（close 与前收，缓存范围外不补造）。
- 导出缓存文件给前端：静态 JSON（同源、不经过网络）＋ 支持范围声明；断网可算。

**风险**

- 清单与证据未到位（M1/M2）是冻结阻塞项；在签收前，页面只能用合成夹具并如实标注。
- 复权基准（adjustment_basis）口径易与抓取时间混淆（B6 已禁止代用）；核验记录缺失会导致前复权展示口径不可审计。
- 缺价/事件阻断会"碎块化"结果（部分可算部分阻断）——UI 需要清晰的逐标的阻断标注，且组合不按剩余标的冒充完整（B4/B5）。
- 真实行情源为第三方接口（akshare 上游），拉取时点、字段口径与稳定性的证据链需要在 M0-C2 留存。

## 3. 百炼（LLM）

**字段**

- 在线调用（M1-C10）：`{intent(12 类), slots, confidence}` 意图 JSON；事实 JSON 复述输出；元数据 `{llm_mode: online | offline_fallback, latency, 调用记录引用}`（R3）。
- 出站白名单（F-6/R5）：允许 `value / unit / display / formula_ref / 匿名 source_ref / 必要行为标签`；禁止原始成交行、账户信息、真实订单编号；**用户问题文本纳入隐私核验范围**；意图分类调用不带账单内容。
- 降级：超时 8 秒/网络失败→标注"离线模式"，不得伪装实时。

**依赖**

- M0-C3/C4（changer）：百炼 JSON mode（非思考）连通 + OSS＋函数计算代理连通（Key 不在前端）。
- planner（M1-C6）：意图分类为 planner 的输入；工具注册表 schema 待 M0-C1 冻结。
- 计算引擎：事实 JSON 的数字与 display 字段（确定性层生成，LLM 原样引用）；数字子集校验（回答数字 ⊆ 事实 JSON）。
- 语料：20 问清单（M0 内 Qoder 起草→负责人审校）作为 M1-C10 验收。

**风险**

- 中文数字子集校验可靠性（基线风险 5）：需同时覆盖阿拉伯数字与中文数字表述的抽取与比对。
- 超时/网络抖动会频繁触发降级——降级链路的提示与 trace 记录要可演示（R3）。
- 出站白名单审计要求逐字段核对（DevTools＋代理请求体）；任一新增字段都要过隐私核验，收紧于"发最少事实"。
- 代理与 Key 管理属外部资源（OSS＋函数计算），连通性证据与调用记录（不含 Key）是 M0 退出条件。

## 4. planner（确定性规划）

**字段（附A.1）**

- 输入：用户问题；上下文 `{口径, 契约[], 被证伪假设[]}`；意图 JSON `{intent, slots, confidence}`（12 类，F-8）；工具注册表。
- 输出：`plan {plan_id, intent, template_id/composition_reason, steps[{tool, params}], fallback_used}`。
- 日志（JSONL）：`{ts, plan_id, question_hash, intent, confidence, template/composition, steps[{tool, params_digest, status, ms}], fallback_used, outcome}`。
- 失败路径：意图 JSON 非法→重试 1 次→out_of_scope 合规模板（零工具调用）；slot 失败→澄清/兜底；schema 校验失败→兜底管线；工具异常→中止该步＋降级记录。

**依赖**

- 工具注册表 schema（M0-C1，待冻结）与计算/复核/契约等工具的实现（M1-C3..C8）。
- 意图全集与芯片映射（F-8）；越界话术细则（§7-9，M0 接口冻结项）。
- trace 审计（M2-C6，changer）：四条消息＋回流记录。

**风险**

- "现场规划"叙事与确定性实现的落差（基线风险 3）：未见问题≥10 条实测（M2-C3）是拆穿/验证点，planner 的模板＋组合必须可解释。
- 意图 JSON 非法与 slot 歧义是常态输入边界，兜底路径（零工具调用/澄清）会被演示拷问，需要稳定话术。
- 工具异常时的降级记录是审计要求，steps 状态必须逐条落日志。

## 5. 契约匹配

**字段（F-5/F-9、§4-7）**

- 契约对象：`{文本, 阈值, 哈希, 版本, 状态机：候选→已确认/已改写/已拒绝→已触发/守约/违约, 申报记录（关联契约版本）}`。
- 解析：首版支持"明确规则模板＋可编辑字段"；保存前展示解析出的条件、阈值与提醒内容；自由文本不支持则明确提示（不猜测、不静默默认阈值）。
- 历史情境模拟：选缓存支持的标的与历史日期→读取该日涨跌幅并显示日期与数据来源→"模拟申报买入"→确定性匹配函数判定：命中→警告；未命中→未触发；缺失行情→明确提示。预置案例含触发/不触发两种，与用户操作**共用同一判定链路**。
- 持久化：契约＋申报记录＋哈希（R4：刷新后恢复且哈希一致→匹配仍触发）；修改契约不改变历史行为识别标准（F-5）。

**依赖**

- 行情缓存：历史日期与涨跌幅（需 close 与前收；范围外不补造）——契约模块直接依赖 §2 的清单到位。
- CSV 交易记录：相似情境提醒（历史"卖出即买回"等）与守约/违约回看（F-10 清单为事实出口）。
- 存储层：现仅 `src/state.js` 的 localStorage 演示级记录（无哈希）；R4 的哈希算法与记录结构未定（M0 接口冻结）。
- 匹配纯函数（M1-C11 尹辰）：阈值参数由用户确认/修改（如 5%→3%），解析结果先展示再保存。

**风险**

- 自由文本解析边界：宁缺毋滥（不猜测）；真实用户规则表述多样，首版模板覆盖面需要预置案例兜底。
- 哈希与版本一致性：刷新恢复要求哈希可复算（契约文本归一化规则需冻结，否则"一致"不可判）。
- 措辞合规：历史行情不得称"今天的行情"；警告只陈述"你的规则在当前情境下命中"，不构成荐卖/荐买。
- 演示路径依赖行情缓存真实落地进度（F-9 在 M2）；在此之前入口保持禁用占位（现状）。
