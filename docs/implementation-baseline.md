## 2. 已确认决策记录（15/15 · 2026-10-10）【已确认】

### 2.1 M0 门槛组

**F-1 反事实口径**
- 对外主口径＝单笔反事实（"假如这笔没卖"）；组合口径并存、备询切换（`PRD:148`）。
- 准备"假如早卖/买入侧"备用演示页（S3）：Q&A 被问"该卖没卖"时当场演示；主脚本（`PRD:191-199`）不变。
- Q&A 口径切换规则：单笔问题→单笔口径；整体表现→组合口径；问题含糊→先澄清；买入侧与卖出侧都保留（`PRD:261`、`PRD:265④`）。

**F-3 现价时点**
- 固定 asOfDate 作为数据集元信息（并入行情缓存声明）。
- 产品运行时不允许随意更改截止日。
- 请求超出行情支持范围必须显式提示（与 R2 联动）。

**F-4 资金处置**
- 卖出资金不再投资、按现金面值计入实际结果、不计息（与 `PRD:141` 公式一致）。
- 补充费用/税费/分红口径；CSV 缺失费用字段时按 0 处理并必须在页面标注。
- 计算细则（佣金/印花税/分红除权处理）并入 M0 接口冻结（CSV 列定义）。

**F-6 上云数字白名单**（固化进 R5 与导入页隐私声明，`PRD:104,249`）
- 按 intent 最小化发送事实 JSON；允许字段：`value、unit、display、formula_ref、匿名 source_ref、必要的行为标签`。
- 禁止发送：原始成交行、账户信息、真实订单编号。
- provenance 主要留在浏览器本地。
- 调用①意图分类仅带用户问题文本（**用户问题文本纳入隐私核验范围**）、不含账单内容（`PRD:123-125`）。

**F-8 意图全集与语料**
- 12 类 intent：worst_trade／loss_overview／pattern_explain／profile／what_if／similar_context／how_to_change／contract_setup／contract_status／meta_calc／meta_trust／out_of_scope。
- 芯片映射：最错一笔→①／为什么追高→③／怎么改→⑦／我是谁→④（`PRD:92`）。
- "20 个高频问题"（`PRD:296`）由 Qoder 起草→负责人审校，**在 M0 内完成**，作为 M1-C10 验收语料。

**C 排期**

- M1 至 10/16、M2 至 10/23、M3 10/24–25。

**E 缓存支持范围**
- 必须落成明确清单：具体 3 只股票、起止日期、前复权口径、缺失日期处理方式。
- 范围外一律显示"不支持/数据缺失"；禁止静默外推/缺失填充。
- 清单由 M0-C2 产出草案 → 负责人签收；缺失日期处理具体规则在 M0 接口冻结定稿。

### 2.3 M2 细节组

**F-2 展示与舍入**
1. display 由确定性计算层生成，LLM 原样引用、不自行格式化（F-6 白名单已含 display）。
2. 主界面收益率/损耗百分点 1 位小数；收益率用 %、收益率之差用 pp。
3. 金额 2 位小数＋千分位；验算视图展示必要的更高精度。
4. 计算保留原始数据精度，不使用展示值参与计算，不反复舍入；最终展示统一四舍五入。
5. 复核不以"屏幕显示相同"为通过条件；金额按统一舍入规则比较到分，收益率另设数值容差（具体值随 M0 复核接口冻结）。
6. 正负号：损耗＝对照收益−实际收益；正值＝相对损耗，负值＝实际操作优于对照。

**F-5 阈值与契约**
1. 行为识别参数：按 PRD 完整规则固定（回看窗口/阈值/占比条件），集中配置并记录版本；首版无用户调参面板；方法说明展示规则，但不宣称阈值为已验证的普适标准。
2. 用户契约参数：用户可确认或修改自己的规则（如 5%→3%）；修改契约不改变历史行为识别标准。
3. 契约解析：首版支持明确规则模板＋可编辑字段；保存前展示解析出的条件、阈值与提醒内容供确认；不支持的自由文本明确提示——不猜测、不静默套默认阈值。
4. 契约版本化：修改后的契约保存为新版本；历史申报记录关联当时的契约版本。

**F-7 标注模板**
1. 概念图/PPT 静态示意："界面概念示意·非真实数据"。
2. 预置演示账单运行结果："演示数据·基于公开历史行情与演示账单计算"＋"非真实账户交易结果，不构成投资建议"。
3. 用户上传 CSV 运行结果："基于当前上传交易记录与可用历史行情计算"＋"计算结果仅反映输入数据，不构成投资建议"。
4. 统一：禁止"真实跑出/真实用户收益"表述，**禁止将演示账单冒充真实账户收益**；经验证的代码运行结果可以称为**"实际运行计算"**，并标明数据与口径；结果必须标注数据来源、行情截止日、计算口径。

**F-9 契约触发入口**
1. 入口标注"历史情境模拟"：用户选择缓存支持的标的与历史日期；系统自动读取该日涨跌幅并显示日期与数据来源；不将历史行情称为"今天的行情"。
2. 点击"模拟申报买入"后由确定性契约匹配函数判断：命中→警告；未命中→未触发结果；缺失行情→明确提示，不补造数值。
3. 预置案例至少含"触发/不触发"两种；预置按钮只填入标的、日期等输入，与用户操作**共用同一判定链路**，不能直接播放固定弹窗。
4. 警告展示用户确认的规则、阈值与当前情境事实；用户选择及当时的契约版本写入模拟记录，刷新后可恢复。
5. 首版不开放任意填写行情涨幅；在声明的数据范围内保留真实交互。

**F-10 行为发现交付形态**
1. 报告页提供"行为模式清单"区块（清单页为主）。
2. 每条模式至少含：模式名称；结论状态（成立/证据不足）；样本数 n；对应成交记录 ID；规则阈值与检验方式；可展开的证据与计算路径。
3. 样本不足时显示"证据不足"，不生成确定性结论。
4. Agent 对话可解释清单模式（如"为什么说我追高"），但回答必须引用对应模式卡与成交明细。
5. 对话结论提供"查看证据"按钮，跳回对应清单项。
6. 不做完整的重复标签系统；**"清单是唯一事实出口"限定于行为发现模块**（其他工具可生成有证据支持的事实），对话是行为清单的解释入口。

### A.2 独立复核（`slide-5:142-146`）

| 字段 | 内容 |
|---|---|
