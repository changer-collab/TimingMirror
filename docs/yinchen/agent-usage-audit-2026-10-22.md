## 0. 一句话结论

TimingMirror 现在不是“一个什么都能聊的 AI”，而是**一套确定性账本 + 七个很窄的模型辅助环节**。模型只负责“把已算好的事实说成人话、把自然语言填进固定模板、把图片/文字整理成草稿”，不负责算账、判定规则命中、生成规则、发布报告或替用户做决定。

AI 问答页目前只完成了“组合整体表现如何？”这一条在线复述；悬浮助手反而更完整，已经有五个账单问题、页面 FAQ 和规则候选。下一步不应该把独立页做成通用聊天，而应该把悬浮助手已经验证过的能力，升级成一个“可看证据的问答工作台”。

## 1. “Agent”在本项目里具体指什么

代码里没有通用 agent 框架，也没有自主规划、工具循环或自动执行。实际存在的是七条受控链路：

1. 悬浮 AI 助手：五个账单问题 + 页面 FAQ + 自由文本
2. 独立 AI 问答页：目前只有组合表现一条在线复述
3. 规则助手：自然语言 → 规则草稿（不保存）
4. 规则未命中 AI 判断：只判断“没有规则覆盖”，不生成规则
5. 报告行为分析：AI 给确定性行为事实写短评论
6. 导入 AI：文字/截图 → 可编辑交易草稿
7. 模拟结果解释：解释某条规则本次为什么命中/未命中

另外还有一层**确定性问答骨架**：`planner.js` + `qaChips.js`。它不调用模型，负责把五个固定问题映射成计划、模板和本地答案。

## 3. 七条链路逐一说明

### 3.1 悬浮 AI 助手（当前最完整）

**入口**：`assistantPanel.js` 在 `globalAssistant` 为真时挂载 `renderQaAssistant`；真实前端 `realBridge.js` 已设为 `true`。

**页面感知**：
- 首页、导入、报告、问答、规则页各有自己的简介和 FAQ。
- 页面上下文会显示：当前页、账单是否确认、报告是否发布、行情截止日、规则版本数。
- 规则页在内部仍使用 `contract` 路由（`realBridge.setRoute` 把 `me` 映射为 `contract`）。

**五个芯片**：

| 芯片 | 问题 | 数据来源 | 在线 | 主要失败码 |
|---|---|---|---|---|
| 最错一笔 | 我最错的一笔是哪个？ | 组合分解第一项 | 否 | `W_QA_DECOMPOSITION_UNAVAILABLE` / `_BLOCKED` |
| 为什么追高 | 为什么说我追高？ | 行为包 `chase_high_buy` | 否 | `W_QA_BEHAVIOR_UNAVAILABLE` |
| 怎么改 | 我该怎么改？ | 行为包 + 规则状态 + 画像 → 规则候选 | 否 | 行为不可用/候选不可用 |
| 我是谁 | 我是谁？ | 行为包；账单交易数兜底 | 否 | 无行为时只报账单事实 |
| 组合表现 | 组合整体表现如何？ | 已发布四事实 | **是** | `W_QA_REPORT_WITHHELD` / `W_QA_DECOMPOSITION_UNAVAILABLE` |

**本地芯片的共同门禁**（`qaChips.js`）：
1. 必须是已确认的本地账单；
2. 必须有报告 bundle；
3. `bundle.status !== 'blocked'`；
4. `bundle.review.portfolio_published === true`。

**本地芯片的关键设计**：
- 只读**已缓存**的已发布报告；缓存没有时，悬浮助手会提示“先打开报告页”，不会为了一个本地问题去跑行情。
- 回答包含 `text / facts / evidence / candidate / notice`，不是一段裸文本。
- `how_to_change` 的规则候选带模板、字段、依据、证据、注意事项和状态（可用/已启用/已忽略），但没有“一键保存”。
- 规则状态变化后，候选会标记过期；账单事实仍保留。

**在线路径**：
- 只有点击「组合表现」才走在线；自由文本也会走在线。
- `qaDeps.askOnline` → `createChatOnline().ask` → 固定 `intent: loss_overview, scope: portfolio` → `prepareAnswerFacts` / `exportFacts` → `onlineBoundary.restate`。
- 只允许四个事实：`actualRet`、`ghostRet`、`drag`、`dragMoney`。
- 返回后本机再做数字核对；核对失败即回退固定说明。

**已发现的问题**：
- 悬浮助手的自由文本**没有**调用 `isSupportedChatQuestion` 做范围门禁。即使问“我最错的一笔是哪个”，只要没有精确命中芯片问题，也会带着组合四事实去请求复述。模型受 system prompt 限制只能引用这些事实，但问题与事实不匹配时，结果可能答非所问。独立页反而做了这个门禁。
- `createQaChipService` 只在测试中使用；生产代码直接调用 `buildLocalChipAnswer` / `buildLocalPortfolioAnswer`。两套入口增加了后续维护成本。

### 3.2 独立 AI 问答页（当前最弱）

**文件**：`prototype/user-frontend/realChat.js`

**现状**：
- 只有一个固定问题：`组合整体表现如何？`
- 有一个建议按钮，点击后发送该问题。
- 自由输入先用 `isSupportedChatQuestion` 拦截；只支持“组合/整体/账户/持仓/总体 + 表现/收益/盈亏/损耗/差距”等有限说法。
- 不支持的问题在本地直接回“当前只支持组合四项已发布事实”。
- 发送后调用 `demo.loadChatReview(state.bill)`，再调用 `createChatOnline().ask`。

**与悬浮助手的关键差距**：

| 能力 | 悬浮助手 | 独立问答页 |
|---|---|---|
| 五个账单问题 | 有 | 无 |
| 页面 FAQ | 有 | 无 |
| 报告缓存优先 | 有（本地芯片不跑行情） | 无；每次提问走 `loadChatReview` → `loadUserBillReport`，会经过行情阶段 |
| 报告未发布/阻断提示 | 有 | 有，但只有失败文案 |
| 事实/证据/候选展示 | 有 | 无；只有一段回答 + 技术详情 |
| 账单上下文隔离 | 有 `billContextId` 过滤 | 有 `contextId`/`requestId`，但无历史账单过滤 |
| 在线失败后的报告入口 | 有 | 只有文字 |
| 自由文本范围门禁 | **无** | 有 |
| 规则候选承接 | 有（去规则页确认） | 无 |

**结论**：独立页不是“悬浮助手的全屏版”，而是一套更早、更窄的重复实现。它没有复用 `qaChips`、`qaDeps`、`getRealReportBundle`，也没有使用已缓存的已发布报告 bundle。

### 3.3 规则助手（自然语言 → 规则草稿）

存在两条不同的入口，能力不一致：

| 入口 | 端点 | 支持模板 | 说明 |
|---|---|---|---|
| 悬浮助手「让 AI 理解」 | `/api/llm/rule-intent` | 2 个：`no_buy_on_surge`、`no_buy_back_within` | `ruleAssistant.js` 白名单 |
| 个人中心规则区输入框 | `/api/llm/rule` | 3 个：上述两个 + `sell_within_after_buy` | `ruleIntent.js` + `contractView.js` |

**流程**：
1. 用户输入自然语言规则；
2. 模型只做意图识别和字段建议；
3. 程序用白名单校验模板、字段、范围；
4. `parseRuleSpec` / `parseContract` 生成确定性规则和哈希；
5. 展示待确认草稿；
6. 用户确认后才写入规则记录。

**模型不能做的事**：
- 不能直接保存规则；
- 不能改写模板；
- 不能绕过字段校验；
- 不能把自由文本直接当可执行规则；
- 不能替用户确认范围（全部股票 / 单个 6 位代码）。

**已知不一致**：悬浮助手只支持 2 个模板，规则页支持 3 个。用户从不同入口描述同一条“买入后 N 日内卖出提醒”，一个入口能识别，另一个会说不支持。这是产品/UX 问题，不是模型问题。

### 3.4 规则未命中 AI 判断（吴涵晶负责方向）

**入口**：`contractView.js` 的情景模拟完成后自动触发。

**触发条件非常窄**：
1. 行情来源必须是 `dynamic-tushare`；
2. 模拟结果有效，且有 6 位标的和日期；
3. 当前规则全部未命中（`triggered === 0`）；
4. 规则集合在请求期间没有变化。

**请求内容**：
- 情景：标的、请求日期、生效日期、动作、涨跌幅、当前规则列表；
- 规则：模板、字段、范围、版本、哈希、逐条 verdict/code；
- `rule_set_hash` 由排序后的规则哈希计算。

**响应限制**：
- 只允许 `judgment === 'no_match'`；
- 只允许一段不超过 1000 字的解释；
- 禁止 URL、CSV/XLSX/PDF、原始账单、账户、银行卡、身份证、手机号、买卖建议、预测、荐股、“会涨/会跌”；
- 前缀/绑定字段必须与请求完全一致。

**模型不能做的事**：
- 不能声称命中了某条规则；
- 不能生成新规则；
- 不能修改/保存规则；
- 不能在已有规则命中时覆盖规则结论。

**结论**：这项任务现在实现的是“AI 判断为什么没有规则覆盖”，不是“AI 自动补一条规则”。如果组长说的“规则库扩充”包含自动生成新规则，那还没有做，需要另行设计模板和确认流程。

### 3.5 报告行为分析

**入口**：报告页在存在行为模式时自动请求，不需要用户点击。

**请求**：
- `behavior-facts-v1`
- 只包含 `protocol / events / buy_windows`
- 事件只有 `side / asset_key / day_offset`；`asset_key` 是 `A1` 这类脱敏代号
- 至少一笔买入；`day_offset` 非递减；买入窗口必须覆盖全部买入

**服务端**：
- 重新计算交易统计和模式事实（样本数、评估数、证据索引）；
- 模型只能返回 `patterns / observations / rule_candidates`；
- 模式的状态、样本数、评估数、证据索引必须与服务端重算一致；
- 评论最多 80 字，禁止 6 位代码、买卖建议、收益保证、URL、换行；
- 观察最多 2 条，每条至少 2 个证据索引；
- 规则候选必须与本地模式状态完全一致。

**前端**：
- 成功结果按报告 key 缓存；
- 模型失败时服务端返回 `backend_rules` 兜底；
- 网络失败时显示“在线观察暂不可用 + 重试”，不伪造 AI 文本；
- 成功后同步到用户画像（`syncBehaviorAnalysis`）。

**结论**：这是“AI 给确定性事实写注脚”，不是“AI 发现新行为”。事实、样本、证据都由程序决定。

### 3.6 导入 AI

**入口**：导入页；默认本地解析，只有用户点击才调用模型。

**文字识别**：
- 端点 `/api/llm/import-recover`
- 发送提取出的文字（不含文件名、原始文件）
- 返回结构化草稿，仍需逐行校验和用户确认
- 每个导入流程最多 2 次模型调用

**视觉识别**：
- 端点 `/api/llm/import-vision`
- 支持 JPEG/PNG；截图或本地渲染后的扫描 PDF 页面
- 单请求最多 8 张
- 单图 Base64 最多 2,000,000 字符
- 总 Base64 最多 7,000,000 字符
- JSON 请求体最多 7,500,000 字节
- 超限要求缩小范围，不静默截断

**边界**：
- 原始 CSV/Excel/PDF 只在本机读取；
- 预览、选页、本地渲染不触发模型；
- 只有点击识别后才发送提取文字或所选图片；
- AI 生成的只是可编辑草稿，不是“导入成功”；
- 任何必需字段校验不通过，都不会生成正式账单。

---

### 3.7 模拟结果解释

**入口**：规则模拟结果旁的“解释”按钮。

**前置条件**：
- 有当前规则任务 `flowId`；
- 行情可用；
- 最新模拟成功；
- 结果只能是 `triggered` 或 `not_triggered`；
- 必须有真实行情依据、标的和日期；
- 规则版本、范围、模拟结果 ID 必须与当前一致。

**模型输出**：
- 只解释本次规则在本次模拟中的执行结果；
- 不得引入输入中没有的数字、日期、标的；
- 不得预测、荐股、给买卖建议、做组合/总收益结论；
- 返回后前端还会校验绑定关系；规则或结果变化则丢弃旧解释。

## 4. 所有模型端点与数据出站

站点函数路由在 `server/site-functions/handler.mjs`，同源路径为 `/functions/v1/app/api/llm/...`。

| 端点 | 请求内容 | 模型输出 | 关键校验 |
|---|---|---|---|
| `/api/llm/intent` | `{ question }` | 意图 JSON | 字段白名单、confidence；**当前无生产入口** |
| `/api/llm/restate` | `{ question, facts }` | `{ answer_text }` | facts 字段白名单；数字必须逐字引用 display |
| `/api/llm/rule` | 规则文本 | 意图/模板/字段/范围 | 三模板白名单、确定性 parse |
| `/api/llm/rule-intent` | 规则文本 + 允许模板/工具 | 意图/模板/字段/范围 | 两模板白名单、确定性 parse |
| `/api/llm/result-explanation` | 规则 + 模拟结果 | `{ answer_text }` | 绑定校验、禁用内容、长度 |
| `/api/llm/scenario-judgment` | 情景 + 当前规则 | `{ judgment:'no_match', answer_text }` | 规则哈希、字段白名单、禁用内容 |
| `/api/llm/behavior-analysis` | 脱敏行为事实 | 评论/观察/候选 | 服务端重算事实、逐项一致性 |
| `/api/llm/import-recover` | 提取文字 | 结构化草稿 | 字段/行校验、预算 |
| `/api/llm/import-vision` | 所选图片 Base64 | 结构化草稿 | 图片数量/大小/MIME/请求体 |
| `/api/market/snapshot` | 标的与日期范围 | 行情快照 | 非 LLM；Tushare token 仅在服务端 |

**重要发现**：`/api/llm/intent` 的客户端 `classifyIntent` 只有测试调用，没有生产 UI 调用。当前自由问答不是“先分类再回答”，而是直接带着固定组合事实去复述。

## 5. 确定性 vs 模型：谁决定什么

### 绝不由模型决定

- 账单解析的最终行、校验结果、确认状态；
- 收益、对照收益、择时损耗、金额；
- 行为模式是否成立、样本数、评估数、证据索引；
- 规则模板、字段、范围、哈希、版本；
- 规则是否命中、命中哪一条；
- 报告是否发布、是否阻断、哪些事实可出站；
- 回答中的数字是否与本机事实一致；
- 用户画像的确定性统计；
- 导入是否成功、能否生成正式账单。

### 模型只负责

- 把已发布事实复述成自然语言；
- 把自然语言规则描述映射到固定模板；
- 解释某次模拟为什么命中/未命中；
- 给确定性行为事实写短评论；
- 把提取文字/图片整理成可编辑草稿；
- 在无规则覆盖时说“没有覆盖”，并解释原因。

### 用户确认门禁

- 规则保存：必须用户确认；
- 导入账单：必须用户核对并确认；
- 在线复述：只发送最小事实集，不自动上传原始账单；
- 行为分析：只发送脱敏事件；
- 未命中判断：只读，不写规则。

## 6. 数据与隐私边界

| 数据 | 是否出站 | 说明 |
|---|---|---|
| 原始 CSV/Excel/PDF | 否 | 只在本机读取 |
| 文件名 | 否 | 导入文字请求明确不含文件名 |
| 账单原始行 | 否 | 行为分析使用脱敏事件；在线复述只用聚合四事实 |

## 10. 对 AI 问答页设计的硬约束

基于以上能力，独立页不能承诺：

- “什么都能问”；
- “基于整份账单自由分析”；
- “AI 帮你总结所有交易”；
- “AI 帮你生成/保存规则”；
- “问一句就自动跑行情/重算报告”。

独立页可以且应该做：

1. **五个固定问题 + 一个在线组合问题**，与悬浮助手共用 `qaChips` / `qaDeps`。
2. **本地优先**：四个本地芯片只读已缓存、已发布的报告 bundle；缓存没有时给“打开报告页”入口，不自动跑行情。
3. **结构化答案**：正文 + 事实 + 证据 + 候选规则 + 提示 + 可折叠技术详情。
4. **状态完整**：未确认账单、报告未载入、报告阻断/未发布、行为不可用、分解不可用、在线失败、候选过期。
5. **自由文本收口**：
   - 精确命中五个芯片问题 → 走本地芯片；
   - 命中组合表现家族 → 走在线复述；
   - 其他问题 → 本地说明“目前只能回答这些”，不要带着组合事实硬答。
6. **与悬浮助手分工**：
   - 悬浮助手 = 随时问一句、快速看结论；
   - 独立页 = 看完整证据、承接规则候选、处理失败与状态。
7. **不重复实现**：不要在新的 `realChat` 里再写一套 fetch/校验；直接复用 `qaDeps` 和 `qaChips` 的返回结构。

## 11. 建议的页面方向（待确认后细化/画图）

不建议做成通用聊天流。建议做成**“问答工作台”**：

```
┌──────────────────────────────────────────────┐
│ 账单上下文：文件名 · 行情截止 · 报告状态 · 规则版本 │
├──────────────────────────────────────────────┤
│ 你可以问（五个固定问题）                         │
│ [最错一笔] [为什么追高] [我是谁] [怎么改] [组合表现·在线] │
├──────────────────────────────────────────────┤
│ 答案区                                         │
│  · 一句话结论                                  │
│  · 关键事实（标签 + 数值 + 来源）                 │
│  · 证据（可展开）                               │
│  · 规则候选卡片（如有）→ 去规则页确认              │
│  · 提示（报告未发布/数据不足/候选过期/在线失败）     │
│  · 技术详情（默认折叠）                          │
├──────────────────────────────────────────────┤
│ 输入框：只支持这五类问题或组合表现                 │
│ 不支持时本地说明，不发模型                        │
└──────────────────────────────────────────────┘
```

**为什么不是聊天气泡流**：
- 当前能力是固定的五类问题，不是开放对话；
- 聊天气泡会暗示“什么都能问”，与实际能力不符；
- 结构化卡片才能承载事实、证据、候选和状态；
- 独立页的价值是“看得更深”，不是“再做一个悬浮助手”。

**桌面布局**：左侧 220–260px 问题导航，右侧答案工作区；移动端问题导航变成顶部横向滚动。
**视觉**：延续现有少文字、低密度、强对比、克制间距的风格；在线问题用一个小标记区分，不用大面积渐变或“AI 魔法”装饰。

## 12. 说人话版本

把“镜子”想成一个很较真的会计，AI 只是坐在旁边的翻译：

- **算账、对账、判断规则有没有命中**：会计自己做，AI 不碰。
- **五个问题里的四个**：会计直接从已经核对好的报告里翻出事实，翻译成一句话；不联网问模型。
- **“组合表现”**：会计把四个已经核对过的数字交给翻译，让翻译复述一遍；翻译不能自己算，也不能改数字，说完还要被会计逐字核对。
- **规则助手**：像填表助手。你说“我不想追高”，它帮你找到“涨幅超过 X% 不买”这张表，填好数字和范围，但最后必须你自己签字，它不能替你保存。
- **没命中规则时的 AI 判断**：它只能说“现有规则确实没覆盖这个情况，原因是……”，不能说“你应该买/卖”，也不能自己加一条规则。
- **报告里的 AI 观察**：会计先算出“你追高了 3 次、证据是这几笔”，翻译只负责写一句人话评论；翻译写错或乱编，整条作废，退回规则引擎的版本。
- **导入 AI**：像 OCR 实习生，把截图/文字整理成表格草稿；原始文件不离开你的电脑，而且最后要你逐行核对。
- **现在的独立问答页**：只学会了问“组合表现如何”，其他四个问题还没有搬过去；悬浮助手反而更聪明，已经会五个问题。

所以下一步不是“让 AI 更自由”，而是“把已经会的东西摆到独立页上，让用户看得到证据、知道什么时候不能用”。
